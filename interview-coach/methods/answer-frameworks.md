# 答题方法论

这份文件是「面镜」生成答题框架时参考的方法论，可以直接在页面「方法论」里编辑，也可以用任何文本编辑器修改。

格式约定（程序会解析，改内容随意，格式请保持）：

- 一级标题 `#` 只出现一次。
- `## 通用原则`、`## 记忆方法` 是两段通用说明，会整体交给分析模型参考。
- 其余每个 `## 名称` 是一个答题框架，下面用 `- 字段：内容` 的形式写字段。
  - `适用题型`：用英文逗号分隔，可选值 self_intro / resume / case / scenario / behavior。
  - `骨架`：用 `→` 分隔的步骤，每一步会变成答题卡上的一格。
  - `口诀`：方便记忆的短句。
  - 其他字段（开场句、时长、常见错误、示例）随意写，模型会参考。
- 想新增框架，复制一段 `##` 改名改内容即可。

## 通用原则

- 结论先行：第一句话就给结论或定性，面试官听 10 秒就知道你要讲什么。
- 一段一个点：每段只讲一件事，用「第一、第二、第三」或「先、再、最后」显式分段，语音场景下面试官没有字幕，结构必须说出来。
- 数字是锚点：每个案例至少带一个数字（量级、比例、时效、前后对比），没有数字就说「量级大概是……」，不要完全空着。
- 讲「我」不讲「我们」：讲清楚哪一步是你判断的、你推动的，团队的部分一句带过。
- 准备两个长度：30 秒版本（只讲骨架）和 2 分钟版本（骨架 + 细节）。面试官追问再展开，不要一上来就讲满。
- 收尾要落地：最后一句讲结果、沉淀或反思，不要停在「然后就这样了」。

## 记忆方法

- 一题一张卡：每道题只记「口诀 + 3-5 个关键词」，不要背整段话。开口时按关键词往下讲，句子现场组织，听起来才不像背稿。
- 口诀用首字串联：把骨架每一步取一个字，例如「象因处标环」（现象、归因、处置、指标、闭环），默念一遍就能找回顺序。
- 数字锚点单独记：把案例里的 2-3 个关键数字写在卡片最上面，数字记住了，故事自然能串起来。
- 素材复用：准备 3 个核心案例，覆盖「处理过的 badcase」「推动过的策略/机制」「跨团队冲突」。大部分经历题、案例题都能从这 3 个案例里选一个讲，不需要每题准备新故事。
- 出声练习：每张卡至少大声讲 3 遍，第 1 遍看卡，第 2 遍只看口诀，第 3 遍什么都不看并计时。

## 三段式自我介绍

- 适用题型：self_intro
- 骨架：我是谁（一句话定位） → 凭什么（两三个代表经历和结果） → 为什么来（和这个岗位的连接）
- 口诀：谁 · 凭 · 为
- 时长：60-90 秒
- 开场句：我是 XX，过去 N 年一直在做 XX，最核心的经验是 XX。
- 常见错误：按时间线流水账；罗列职责不讲结果；最后没有落到这个岗位。
- 示例：我做了三年内容安全运营，主要负责大模型生成内容的策略和 badcase 治理。代表性的两件事，一是……把漏放率从 X 降到 Y；二是……。这次看这个岗位，是因为……

## 案例五步法

- 适用题型：case, resume
- 骨架：现象（发生了什么、影响多大） → 归因（怎么定位到根因） → 处置（先止损再修复，我做了什么） → 指标（用什么数据证明有效） → 闭环（沉淀了什么机制）
- 口诀：象 · 因 · 处 · 标 · 环
- 时长：2 分钟
- 开场句：我讲一个 XX 的 case，结论是根因在 XX，最后通过 XX 把 XX 指标从 A 改善到 B。
- 常见错误：只讲流程名词不讲判断过程；归因停在「模型能力不足」；没有前后对比数据；没有讲机制沉淀。
- 示例：这是内容安全岗位最常用的结构，本质是 STAR 的加强版，把 Action 拆成归因和处置，把 Result 拆成指标和闭环。

## STAR-R 经历法

- 适用题型：resume, behavior
- 骨架：情境（背景和约束） → 任务（我要解决什么） → 行动（我做了哪几件关键事） → 结果（数据和影响） → 反思（如果重来会改什么）
- 口诀：境 · 任 · 行 · 果 · 思
- 时长：90 秒 - 2 分钟
- 开场句：这件事的背景是 XX，我负责的是 XX。
- 常见错误：情境讲太长占了一半时间；行动里全是「我们」；没有反思显得不够成熟。

## 应急四步法

- 适用题型：scenario
- 骨架：定性（判断事件级别和影响面） → 止损（先用什么手段把风险压住） → 归因（同时排查原因、分工） → 长效（事后机制、预案、复盘）
- 口诀：定 · 止 · 因 · 长
- 时长：2 分钟
- 开场句：我会先花几分钟定性，判断这是不是需要升级的事件，然后分两条线走：一条止损，一条归因。
- 常见错误：一上来就讲长期方案；没有讲优先级和时间线；忽略升级机制和对外口径；只靠加人审。
- 示例：场景题可以按时间轴讲：前 15 分钟做什么、1 小时内做什么、当天收尾做什么，面试官最容易跟上。

## 冲突对齐法

- 适用题型：scenario, behavior
- 骨架：共识（双方共同目标是什么） → 分歧（具体卡在哪个点） → 数据（用风险量化把分歧变成可讨论的数字） → 方案（分层/灰度/兜底，给出可选项） → 边界（哪些底线不能让）
- 口诀：同 · 异 · 数 · 案 · 底
- 时长：90 秒 - 2 分钟
- 开场句：我会先确认我们的目标其实是一致的，都是 XX，分歧在于 XX。
- 常见错误：把对方说成反派；只讲立场不讲方案；没有底线或底线说不清。

## 指标取舍法

- 适用题型：resume, case
- 骨架：定义（指标口径怎么算） → 局限（口径有什么偏差） → 取舍（冲突时按什么原则选） → 兜底（取舍带来的风险怎么补）
- 口诀：义 · 限 · 舍 · 兜
- 时长：90 秒
- 开场句：先说口径，我们的漏放率是按 XX 抽样、XX 分母计算的。
- 常见错误：说不清分母；只说「两个都重要」；没有讲按风险等级区别对待。

## PREP 观点法

- 适用题型：behavior, self_intro
- 骨架：观点（先亮结论） → 理由（一到两个理由） → 例子（一个真实经历） → 重申（回到观点并落到岗位）
- 口诀：点 · 由 · 例 · 回
- 时长：60 秒
- 开场句：我的看法是 XX。
- 常见错误：理由太多太散；例子和观点对不上；最后不收回来。
